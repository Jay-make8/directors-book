# 场景资产

为每个场景写给文生图模型用的提示词。生成的图作为视频提示词里的「场景」参考，锁定空间和影调。

## 输入

- 剧本交接结构里的**场景信息表**和场次（见 `script-common.md`）；分镜里这个场景出现在哪些镜头、需要哪些角度和走位。
- 用户已有的场景图：直接复用，不重做。
- 已经问过画幅和模型版本（见 `ask-before-start.md`）。**场景母版的画幅和视频画幅一致。**

## 几类图和三个档位

| 图 | 管什么 | 每个场景 | 上传给视频模型吗 |
|---|---|---|---|
| **母版**（正打） | 这个场景长什么样：布局、材质、光、色调、气氛；也是主机位 A 那个方向看过去的样子 | 1 张，必出 | 本段有镜头朝这个方向拍时上传 |
| **反打** | 从母版的另一头回看：母版背后那一面（入口、后墙、门窗）长什么样 | 1 张，常规和复杂场景必出，排在母版之后 | 本段有镜头朝这个方向拍时上传 |
| **俯视图** | **推演空间关系的主要依据**：家具、门窗、通道各在哪里。写实的顶拍，像把屋顶掀掉往下看。从母版和反打两张推出来，母版、反打和用户给的参考优先 | 1 张，常规和复杂场景出，排在反打之后 | 常规场景每段都传；复杂场景改传走位图（它就是在俯视图上加画的） |
| **角度图** | 正打、反打之外，镜头要用的方向（侧面、从门口往里看、高位）：从那个位置看过去长什么样 | **按需**，一个方向一张单图（见下面「角度图」） | 本段有镜头朝这个方向拍时上传 |
| **走位图** | 在俯视图上叠加人物分段站位、路线和对话轴线 | 0–1 张，复杂场景才出 | 上传（代替俯视图）；有没有帮助没验证 |

| 档位 | 出哪些 | 什么时候 |
|---|---|---|
| 简单场景 | 母版 | 单个镜头、不换方向、一次性过场 |
| 常规场景 | 母版 + 反打 + 俯视图，再加镜头要用的角度图 | 大多数对话场景 |
| 复杂场景 | 再加走位图 | 多人走位、动线复杂、有对话轴线、机位多 |

**为什么常规场景固定出反打**：一张母版只拍到一个方向，摄影机一掉头，背后那半个空间就是模型现编的，反打最容易崩。先补一张反打，空间的两头就都有图了；再拿这两张推俯视图和其他角度，要猜的部分少得多。反打不是「按需」：对话戏最常见的就是正反打，固定出这一张，也免得写分镜时为了少出一张图而回避反打（`storyboard.md`「合镜检查」：一切为剧本和剧情服务）。

**出图的顺序**：母版 → 反打（只传母版）→ 俯视图（传母版和反打）→ 角度图（传母版和反打）→ 走位图（传俯视图）。每一步出单张图。

**每段上传哪几张**：本段出场的人物图 + 俯视图（复杂场景换成走位图）+ **本段镜头实际朝向的那几个方向的图**（正打就是母版、反打、角度图）。一个方向的镜头都没有，就不传那个方向的图；也不为了用上某张图去加镜头。例：两人正反打的一段 = 两张人物图 + 俯视图 + 母版 + 反打。**不用宫格**：一张图里拼几个角度，模型可能把各格当成连续镜头，用不到的格子也会让它多一次自由发挥（官方指南对主体参考也建议多视角拆成几张单图）；只有 Seedance 2.0 的 9 张额度不够时，才把两个方向拼成一张两宫格省一个名额（写法见下面「场景多机位（宫格，额度不够时）」）。

**有了参考图的这几步，提示词写得越短越好**：2026-11-02 用《雨夜修表匠》实测过，一句话出的写实俯视图，母版里的家具几乎一件不差；把出图前写的布局描述抄进提示词，文字和母版对不上，模型照文字画错了。**但从图推出来的图都有推测**：母版和反打都看不到的地方（侧墙的拐角、建筑背面、屋顶），是模型补出来的，当作未知，不当成已经验证的结构；剧情要拍那里，就补一张那个方向的角度图。俯视图和角度图出来后，逐项对照母版、反打和用户给的参考（入口、台阶、窗、屋顶、家具、通道），对不上的以它们为准，不改空间事实去迁就新图。

同一个视频里地点很多时：主要场景（反复出现、有走位）按常规或复杂档出；次要场景（出现一两次、只朝一个方向拍）只出母版；过场场景不出图，用文字写清楚。图片额度按**每个片段**算，数字见 `models.md`；超了就先拆片段。

**这几类图都是纯场景，画面里不放人物、人影、动物。** 尺度靠台阶、门、脚手架这类参照物建立。走位图里的人物只用字母和箭头表示。

**每张方向图记下朝向**（母版、反打、角度图）：摄影机朝哪个方位拍（按空间事实里的方位，例如母版朝北、反打朝南），写进交付说明的《方向图对照表》，导演手册里写进这条提示词的 `facing` 字段，脚本用它查「镜头朝的方向有没有图」（见 `readback.md`）。

## 空间事实（先定，后面所有图和提示词都引用）

先把这个场景的空间事实写成一小段，**只写一次**，母版和视频提示词都原样复制它，不要各写各的（反打、俯视图、角度图、走位图的提示词以图为准，不再抄它；反打的背景按这里写的入口、门窗、固定物写）：

- **布局一句话**：固定物**之间的关系**（什么挨着什么、什么在什么前面、隔着什么相对），**不写画面左右**。例：脚手架和板房宿舍隔着一片空地相对，板房门前有两级水泥台阶，台阶正对着空地。这一句会原样复制进视频提示词，而一个片段里机位会换，写了画面左右，反打的镜头就会被它带错；画面左右只在母版的【空间分层】里按主机位 A 写一次，视频里每个镜头按机位推。
- **方位**（内部用，不进任何提示词）：给场景定好东南西北，写清固定物各在哪个方位；定法和怎么翻译成画面左右见 `camera.md` 基础第 16 条。
- **主入口和次入口**在哪里，门朝哪个方向开。
- **固定物清单**：门、窗、台阶、立柱、大件家具，各在哪里。
- **年代与地域**，加 3–5 个一眼认得出年代的元素，加几个不该出现的元素（例如写现代的就不要出现马车、煤油灯）。
- **空气**：这个场景的空气是什么状态（清洁、有薄灰、有雾），来源是什么。不要留空，不确定就写「清洁空气，无介质」。

**母版出图后，以图为准**：实际出来的母版和这里写的布局不一样（多了一件家具、门换了位置），先按母版改布局一句话，后面各处（视频提示词【整体概念】）用改后的那一句；不要拿出图前的计划去对抗已经出来的图。反打出图后同理：母版背后那一面的入口、门窗和这里写的不一样，按反打改。

场景在剧情里发生**持续**变化（损毁、停电、下雨、闪回前后），而且跨 2 个镜头以上时，要单独出一张**状态版**：共享同一个空间布局和固定物位置，只改变状态层，不要画成两个空间。只跨一个镜头的变化，用文字在分镜里写清楚即可。

## 母版

七个块，写成一份连续的提示词：

```
【版式与媒介】
【场景总设定】
【空间分层】
【光影】
【色彩与材质】
【镜头质感】
【反向限制】
```

**【版式与媒介】**：真实电影摄影机拍摄的电影剧照，写实，不是 CG、不是概念图、不是 AI 插画；画幅和视频一致；场景母版，纯场景无人物人影，无文字。**主机位 A**：摄影机站在哪里、朝向哪边、离地多高（平视约 1.5 米）、焦距感（接近 40mm）；透视自然，不做超广角变形。一句话写清，不要写长。

**【场景总设定】**：地点、时代、时段、天气，加上面的年代与地域和空气。

**【空间分层】**：前景、中景、远景；写出布局一句话，再写一句「从主机位 A 看，……在画面左侧，……在画面右侧」（母版只有这一个机位，画面左右只在这里写）。前景只占画面下缘，不放特写碎石。

**【光影】**：主光方向和光源；不允许没有来源的光。

**【色彩与材质】**：颜色用具体的（褪色的灰绿，不是鲜艳的青绿）；材质写得克制，细节密度中等，不逐个刻画每块砖、每粒碎石。

**【镜头质感】**：真实摄影机的观感，暗部不死黑，亮部自然滚降；不做边缘增强，不做局部对比度增强，没有 HDR 感。

**【反向限制】**：用图像底（见 `asset-character.md`），再追加「人物、人影」；按场景追加确有风险的项或出过的问题。

**去 AI 感按题材选，不统一调灰调软：**
- **通用**：先靠真实的不完美细节（使用痕迹、轻微不规整、自然的杂物），而不是把整张图调灰；只修实际出现的问题（过锐、色偏、没有来源的发光、物体边缘的亮橙色描边）。
- **剧情片默认加**：低饱和；冷灰漫射光为主时，暖色只在地平线一小块；不要在物体边缘形成亮橙色轮廓光；不要青橙对比；保留轻微的光学柔化，近处清晰、中景略软、远景明显偏软；反向限制追加「青橙对比色调、高饱和」。
- **展示类（建筑外观、室内空间、产品）**：按用户的参考图和观看目标来，该清楚的保持清楚（建筑材质、结构线条、真实的金色夕照），不加远景偏软和低饱和。先定这个场景最值得看的部位、整体要露出到什么程度，再定机位；不规定建筑占画面高度的统一比例（竖屏放一栋横向的宽房子，高度本来就受宽度限制）。

示例见 `examples/scene-site-master.md`（剧情片）。

> 剧情片的那几条（光学柔化、远景偏软、不要亮橙轮廓光、不要青橙）来自一次出图的反馈（成图过度锐化、青橙配色、边缘有橙色描边），**是推测的原因和对应的改法，对照实验还没有做**；用在建筑展示上会削弱材质和真实夕照，所以改成按题材选。

## 反打（常规和复杂场景）

**从母版的另一头回看**：摄影机站到母版画面的远处，朝原来摄影机的方向拍，画面背景是母版背后那一面。生成时只上传母版（作为 `@图1`）。**背景里有什么按空间事实写**（入口、门窗、靠墙的固定物），不要让模型猜：

```
参考@图1（场景母版），生成同一个场景的180度反打视角：背景是……（按空间事实写母版背后那一面：入口的门、窗、靠墙的固定物）；家具的位置大小形状、材质、色调、光影、氛围和@图1完全一致。纯场景，没有人物，图上没有文字。
```

写法借鉴自一位导演博主的分享（只写「参考图1，生成180度反打视角」有时也行，背景写清更稳）；**在我们的项目里还没有实测**。不加整段反向限制（和俯视图一样是例外）。示例见 `examples/scene-site-reverse.md`。

## 俯视图（常规和复杂场景）

**写实的顶拍**：像把屋顶整个掀掉，从正上方往下看这个空间，材质、光线和母版一致。不是线稿示意图，也不画机位箭头。生成时上传母版和反打（`@图1`、`@图2`），提示词**一句话**就够：

```
根据@图1和@图2（同一个场景的正打和反打）生成这个空间内部结构的俯视图，完整保留所有陈设。
```

室外场景把「这个空间内部结构的俯视图」换成「这个场景的俯视图」。只上传母版、写「根据@图1（场景母版）……」的一句话版在《雨夜修表匠》实测过；加上反打两张一起推是 5.8.0 改的，**还没有对比实测**，反打背后的空间以前全靠模型猜，现在有图可依。

不要把布局一句话、家具清单再写进去：模型会照文字画，文字和图只要有一处不一样，就会画错。需要时最多再加一句「纯场景，没有人物，图上没有文字」（加了是否影响效果还没测）。**俯视图是图像底反向限制的例外**：只写这一两句，不加整段反向限制。

**俯视图出来以后**：能直接读到图就自己读，读不到再请用户发来；**对照它核对分镜**：每个人靠哪件家具站、每一镜摄影机在哪、朝哪拍，画面左右、面对还是背对镜头都从这里推（`camera.md` 基础第 15、16 条）。分镜写在出图之前，实际空间可能和计划不一样，核对完再写视频提示词。**还没有出图就要交付视频提示词时**（用户只要提示词、自己去出图），站位和机位是按布局草案设计的：交付说明里写明「待图片核验」，请用户出图后发来，对不上的地方再改。

示例见 `examples/scene-site-plan.md`。

## 角度图（按需，一个方向一张）

**正打、反打之外，镜头要用的方向才出**（侧面、从门口往里看、高位俯瞰）。由分镜决定：剧情需要这个方向的镜头，就出这一张；不为了用上图去加镜头，也不为了少出图去改镜头（`storyboard.md`「合镜检查」）。生成时上传母版和反打（`@图1`、`@图2`）。

**哪些镜头不需要单独的角度图**：
- 机位朝向和母版或反打差不多（同一个方向，只是更近）：用母版或反打。
- 背景大幅虚化的特写：可以不出，镜头正文写清人物身后是什么。

**每个机位写三样**，和视频提示词写镜头的方法一样（`video-prompt.md` 第 1 项）：摄影机在哪（用场景实物定位置）、朝哪拍（朝哪个实物）、画面里看到什么（前景、远处，必要时写什么不入画）。只写前两样，模型容易往母版的角度靠。

```
参考@图1和@图2（同一个场景的正打和反打），生成同一个场景的一个平视视角：摄影机在……，朝……拍；画面最近处是……，中间是……，远处是……；……不入画。家具的位置大小形状、材质、色调、光影、氛围和@图1、@图2完全一致，不新增、不删除、不移动任何东西。离地约 1.5 米，焦距感接近 40mm。纯场景，没有人物，图上没有文字。
```

选方向时可以参考空间类型（不合适就换，不要硬凑；室内不写「背面全景」「高空鸟瞰」）：

| 空间类型 | 常用的方向（正打、反打之外） |
|---|---|
| 室内（房间、车厢、走廊） | 进门视角（从入口向内看）、侧墙方向、窗侧光位 |
| 室外有建筑（小区、院子、工地、街边） | 侧向全景（沿建筑或场地走向）、入口近景、高位俯瞰 |
| 自然场地（树林、山路、草地） | 侧向全景、低位贴地、通道或窄口 |

示例见 `examples/scene-site-multicam.md`。

## 场景多机位（宫格，额度不够时）

只在 Seedance 2.0 的 9 张参考图额度不够（人多、方向多）时用：把两个方向拼成一张两宫格，只占一个名额。从母版和反打推（或已有的方向图直接拼），每格写法和角度图一样，格数写死：

```
参考@图1和@图2（同一个场景的正打和反打），生成同一个场景的两个平视机位。只生成一张图，左右两格，共 2 格，不多不少；格子位置固定：V1在左、V2在右。家具的位置大小形状、材质、色调、光影和@图1、@图2完全一致，两格是同一时刻的同一个空间。纯场景，没有人物。

V1：摄影机在……，朝……拍；画面最近处是……；……不入画。
V2：……

每格左上角只标一个小号标签：左格标 V1，右格标 V2，图上不要其他文字。

以下内容一律不要出现：人物、人影、第 3 格、拆成多张散图、两格内容不一致、俯视角度、V1和V2之外的文字、水印、logo。
```

标签统一用 V1、V2，标签要小。绑定行写明「只参考空间，不是分镜」。

## 走位图（复杂场景才出）

**在俯视图上叠加人物走位**。它的作用是让分镜里的走位、机位和对话轴线有一张共同的图可以对。生成时只上传俯视图（作为 `@图1`）：

```
在@图1（这个场景的俯视图）上叠加走位标注，图片本身不改：用字母 A、B 标出人物的分阶段站位，用箭头标出每段行走路线的起点和终点；有对话时用一条虚线标出对话轴线；用小箭头标出各镜头的摄影机位置和朝向，旁边写 V1、V2……。图上只写这些字母和标签，不写其他文字。
```

人物用字母 A、B 表示，不要和机位标签 V1、V2 混用。交付说明里写清 A、B 各是谁、这是设计示意，不是实测的建筑图。

**它是写分镜的底稿和自检用的**（对应 `camera.md` 基础第 16 条的调度底稿），也会上传给视频模型代替俯视图。上传后有没有帮助，**没有验证过**；火山引擎《Seedance 2.5 提示词指南》提醒过，轨迹线、坐标线、摄影机标记这类示意符号容易漏进生成的视频，绑定行要写明不进画面。

示例见 `examples/scene-site-blocking-map.md`。

## 参考图里没有的角度怎么补

分镜要拍的方向，母版、反打和已有的角度图里都看不到时（`camera.md` 基础第 17 条），先补一张那个方向的场景图，再写那一镜。**首选：按上面「角度图」从母版和反打补出这一个方向**（出单张）。要连人物一起出角度时，用下面三种办法，提示词由你写；三种都**没有在我们的项目里验证过**，来自一位导演博主的分享。

1. **改图模型改机位**（适合已经有一张满意的画面，只差一个角度）：上传母版或那张画面，写「保持场景、陈设、光线完全不变，只把摄影机移到……（用场景实物说位置），朝……拍，平视，焦距感接近 40mm」。有人物时加「人物的位置和动作不变」。
2. **视频模型原地摇镜一圈，再截图**（适合要好几个角度）：上传母版，写「摄影机位置不动，原地匀速水平摇镜 360°，15 秒刚好转一圈回到起点；画面里没有人物；运动平稳，没有动态模糊」。生成后从视频里截出需要的角度。
3. **生成一段多角度素材视频，挑帧**（适合连人物带场景一起要角度）：上传人物图和场景图，写一段 15 秒、十几个快切镜头的视频，逐条列出要覆盖的角度（建立镜头、面部近景、侧面中景、过肩、反向过肩、高位俯拍、低位仰拍、局部特写），每镜只呈现一个清楚的瞬间。生成后放大，挑能用的画面当首帧或背景参考。这段视频只当素材，不是成片，所以镜头碎没关系。

补出来的图按新的场景图使用：在视频提示词【参考素材绑定】里写清它是哪个角度、只参考空间和背景。

## 说明

几类图的分工、一张图多机位只占一个参考图名额、按空间类型选机位、空间事实先定、状态变体共享布局，这些思路借鉴自 manju-laoli 的场景资产规范，用自己的话改写，并按我们的流程做了调整（角度按需出而不是固定九格、母版画幅与视频一致、标注用 V 编号）。俯视图先行、一句话出俯视图、补角度的三种办法借鉴自导演博主 Shine AI 的场景一致性分享。先补反打、再用正打和反打推其他视角，借鉴自另一位导演博主的短视频（分析见仓库外的案例记录）。一句话俯视图和从俯视图推多机位的写法在《雨夜修表匠》上实测过一轮（2026-11-02）；反打、两张推俯视图、单张角度图是 5.8.0 改的，**还没有实测**。
