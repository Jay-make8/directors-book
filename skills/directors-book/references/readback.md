# 提示词回读校对

**目的**：按调度底稿画的图只是「打算怎么拍」，看不出提示词有没有写对。回读校对是**只拿最终的提示词文字**，还原出模型读到的人物和摄影机调度，画成图，再和调度底稿比；对不上就改提示词，再读一遍，直到对上。

## 什么时候做

1. **交付分镜之前**（必做）：分镜正文就是视频提示词的【分镜】，用户确认过的分镜不能擅自改（SKILL.md 硬规则第 13 条），所以校对循环要在交付分镜、用户确认**之前**跑完，交付时把通过校对的调度图一起给用户看。
2. **写完视频提示词之后**（必做）：加上【整体概念】、参考图说明、反向限制以后再跑一次，查它们有没有和正文打架。这时要改【分镜】正文，先把改动发给用户、等同意再改。

只有一个人、只朝一个方向拍、没有走动的段落，可以只做第 2 次。

## 调度图的规格（所有 agent 一样）

**调度图只用脚本画**（`build_handbook.py`，交付分镜时加 `--layout`），不要自己手画、用图像模型画或换别的工具画，不同 agent 才会出一样的图。找不到 Python 时先问用户要不要安装（`handbook-html.md`）。

**坐标怎么写**（`blocking` 和 `readback` 都按这个写，否则图的比例对不上）：

- 单位是米，按场景的真实大小写（小店铺进深五六米、街道几十米），保留一位小数。
- 原点放在场景西南角，所有坐标都不小于 0；x 往东，y 往北（方位定法见 `camera.md` 基础第 16 条）。
- 固定物是正南正北放的矩形：`x`、`y` 是中心，`w` 是东西方向的宽，`h` 是南北方向的深；斜放的东西按它占的范围近似。
- 人的坐标是站或坐的位置（身体中心）。摄影机的坐标是镜头所在的位置；`look` 是画面中心对准的那个点，优先写成某个固定物或人的坐标。有正反面的道具（手机、照片、屏幕、信）写 `front`：正面朝向的一个点，离道具 0.3–1 米；手机的正面是屏幕那一面。

**画出来的样子**（脚本里固定，不用填）：

| 项 | 规格 |
|---|---|
| 每个镜头一格 | 宽 200 像素，高按场景比例算；北在上，东西、南北用同一个比例，不拉伸 |
| 范围 | 这一格里所有固定物、人、摄影机、道具，四周各留 1 米 |
| 标题 | 左上角「镜头 N」，右上角「北↑」 |
| 固定物 | 细线矩形，名字写在中间；放不下就写在矩形下方 |
| 人 | 实心圆点（半径 4 像素），名字写在左上方 |
| 摄影机 | 红色三角，尖朝拍摄方向；两条红色虚线是大致视野（左右各 24°，约 40mm 焦距感），只是示意 |
| 道具 | 蓝色小方块，短线指向它的正面 |
| 比例尺 | 左下角一条横线，1、2、5、10 或 20 米，取画出来最接近格宽四分之一的那个 |
| 每格下面 | 算出来的画面左右（例如「老周：右」）和道具看到的面 |

核对时的「画外」用的是左右各约 40°（比视野线宽一些，留出余量），在摄影机背后的算「背后」，离视线中心约 4° 以内的算「中」。

## 第一步：盲读

**回读的人只能拿到三样东西**：这一段的提示词文字（【整体概念】和【分镜】；第 2 次加上全部块）、固定物的坐标列表，和上面「坐标怎么写」那几条。**不给剧本、调度底稿、分镜计划**：看过计划的人会不自觉地照计划补，图就画成计划的样子，等于没查。

- **有子代理（subagent）的环境**：每一轮开一个新的子代理，只把上面三样东西和下面的交代发给它。
- **没有子代理的环境**：由你自己读，读之前先把计划放一边，逐句只看这段文字能推出什么；在交付说明里写明「这次回读不是盲读，可靠性较低」。

交代给回读者的话（照这个意思写）：

> 下面是一段视频提示词和场景里固定物的坐标（x 往东，y 往北，单位米）。只根据这段文字，逐个镜头还原：每个看得见的人站在哪（坐标）；摄影机在哪、朝哪个点拍；有正反面的道具在哪、正面朝哪个点。再抄下文字里**明写**的结果：谁在画面左侧、谁在画面右侧、谁不入画、道具画面里看到的是哪一面。**文字没写清、推不出来的不要猜**，写进 `unclear`，说明哪一句、缺了什么。只输出下面格式的 JSON。

回读结果的格式（导演手册里写进这一段的 `readback`；调度底稿写进 `blocking`，格式一样，只是没有「明写的结果」和 `unclear`）：

```json
{
  "rounds": 2,
  "objects": [
    {"name": "柜台", "x": 4, "y": 5, "w": 4, "h": 1},
    {"name": "玻璃门", "x": 4, "y": 0.2, "w": 2, "h": 0.4}
  ],
  "shots": [
    {
      "shot": 1,
      "camera": {"x": 4, "y": 1.5, "look": [4, 6]},
      "people": [{"name": "老陈", "x": 3.5, "y": 5.8}, {"name": "女人", "x": 4.6, "y": 4.2}],
      "props": [{"name": "怀表", "x": 4.4, "y": 5, "front": [4.4, 6]}],
      "screen": {"左": ["老陈"], "右": ["女人"], "画外": []},
      "faces": {"怀表": "背面"},
      "unclear": []
    }
  ]
}
```

- `shot` 是全片镜头号。`objects` 可以只写在 `blocking` 里，`readback` 没写时沿用它。
- `screen`、`faces` 只抄文字明写的；没写就不填，不要自己推。
- `rounds` 写这是第几轮读出来的结果。

## 第二步：画图和自动核对

**交付分镜时**（还没有导演手册），把每段的 `title`、`blocking`、`readback` 写进一个调度数据文件 `{"project": 项目名, "segments": [...]}`，运行 `python3 <skill 目录>/scripts/build_handbook.py 调度.json --layout`，生成一张只有调度图和核对结果的页面（`项目名_调度图.html`），交给用户看；加 `--check` 只在命令行列出核对结果。**整理导演手册时**，这两份数据放进对应段落，运行 `scripts/build_handbook.py` 时，有 `blocking` 或 `readback` 的段落，会在手册「分镜」里这一段下面画出**调度图**（规格见上），有两份数据时上下两排对照（上排调度底稿，下排按提示词回读）。脚本同时算出并核对：

1. **文字自相矛盾**：按回读出来的位置和机位，算出谁在画面左、谁在右、谁在摄影机背后，道具看到哪一面；和文字明写的 `screen`、`faces` 对不上就警告。例：文字写「女子在画面左侧」，但按文字写的机位和站位，她在右边。
2. **和调度底稿不一致**：同一个镜头，回读的画面左右、谁入画、道具看到的面和底稿不同，或者摄影机朝向差得多（超过约 45°）、位置差得远，就警告。
3. **没写清**：`unclear` 不是空的就警告。
4. **缺图**：每个镜头摄影机朝的方向，本段上传的场景图里要有同一方向的图（母版、反打、角度图的 `facing`）；没有就警告「缺图，需要补那个方向的图」，**不建议改机位**（一切为剧本和剧情服务）。反过来，本段上传了某个方向的图、却没有一个镜头朝那个方向，也警告。

算左右的办法：从摄影机朝 `look` 看，人在视线左边就是画面左侧，在右边就是画面右侧；「画外」「背后」「中」的界线见上面的规格。这是平面上的粗算，不管高低和遮挡。

## 第三步：比较和循环

逐镜比这几项，**不比精确距离**：

- 摄影机在两人连线的哪一边、大致朝哪拍；
- 谁在画面左、谁在画面右；面对还是背对镜头、谁在前景；
- 关键道具在哪、画面里看到哪一面；
- 该入画的人都在，不该入画的人有去处（`camera.md` 基础第 19 条）。

**对不上，就改提示词文字**（不是改调度底稿去迁就文字），改完**换一个新的回读者**重读、重画、再比。**最多三轮**。三轮还对不上，多半不是措辞问题，而是调度底稿本身走不通（例如机位在参考图里拍不到、站位和取景冲突）：停下来，把对不上的地方和两排调度图给用户看，问怎么改，不硬改到「通过」为止。

通过后，最后一轮的 `readback` 留在 `handbook.json` 里，手册会画出来给用户看。

## 它查不了什么

- **只读文字**：视频模型还会看母版、反打、俯视图，图和文字打架这里看不出来。
- **回读者也是 AI**：它的理解不等于视频模型的理解。它能抓出明显写错、写含糊、自相矛盾的地方；图上都对，不保证出片一定对。
- 平面粗算：不管人物高低、遮挡、镜头焦段，近处边缘的人可能算成画外。
