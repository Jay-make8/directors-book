# 导演手册 HTML

导演手册 = 剧本 → 分镜 → 资产提示词 → 视频提示词，**交付一个离线 HTML 文件**。版式由脚本固定，每次生成都一样。**不要手写 HTML**，也不要改模板；你只负责产出 `handbook.json`，让脚本生成。

## 什么时候做

四个阶段都做完、用户确认过分镜之后（流程见 `SKILL.md`）。先把剧本、分镜、人物和场景提示词、每个段落的视频提示词都写好，再整理成 `handbook.json`。

## 文件位置

本 skill 目录下：

| 文件 | 作用 |
|---|---|
| `scripts/build_handbook.py` | 读取 `handbook.json`，校验，生成 HTML（只用 Python 标准库，Python 3.8 及以上） |
| `assets/handbook-template.html` | 固定的版式和样式（脚本会读取，不需要你打开） |
| `examples/handbook-sample.json` | 一份完整的填写示例（虚构的小样，两个段落） |

「本 skill 目录」是你读到这份文件的目录往上一层。Claude 通常在 `~/.claude/skills/directors-book/`，Codex 通常在 `~/.agents/skills/directors-book/`，以你实际读到的路径为准。

## 运行

```
python3 <skill 目录>/scripts/build_handbook.py handbook.json
```

- `python3` 换成实际找到的那个（例如 Windows 的 `py -3`）；找不到 Python 先按下面「找 Python；没有就问用户要不要装」处理，不要直接退回 Markdown。
- 默认在当前目录生成 `项目名_导演手册.html`；用 `-o 路径` 指定输出位置。
- `--check` 只校验不生成；`--layout` 用在交付分镜时，输入只有调度数据，只画调度图并核对（见 `readback.md`）；`--md` 生成同结构的 Markdown；`--max-seconds`、`--max-images` 用来覆盖用户平台的单段时长和参考图上限。
- 校验有**错误**就不生成文件，并逐条说明哪个字段有什么问题：按提示补齐后重新运行。错误包括必要字段缺失、引用了不存在的资产、**镜头的结束时间不晚于起始时间**。**警告**不阻止生成，但要读，能改就改。警告包括：镜头标题格式不对、时间不连续、**镜头号不连续**、超过版本的时长或参考图上限、台词列抄了原文、**台词说得太快**（一个镜头里超过约 6 字/秒）、**提示词超过提醒线**（约 2000 字，30 秒约 3000 字；不算参考素材绑定、【摄影与影调】和「光线：」段）、**提示词里的 `@图N` 超出本段上传的张数**、**提示词里出现了「主机位」「母版」这类资产阶段的内部术语**、**台词没有写语气**、**台词列的字数和正文里的台词对不上**、**提示词里有半角标点**、**提示词里写了「轴线」「靠近镜头的一侧」这类抽象机位说法**、**影视镜头缺「光线：」段**、**【摄影与影调】里写了画面左右**等。改 `body` 来消警告时，**不要直接改**：把改后的镜头正文发给用户确认，同意后再替换（见 `principles.md` 第 9 条）。
- **校验通过只说明结构和格式没问题**：站位、道具朝向、取景、关键动作能不能看懂，脚本查不出来，要按 `checklist.md` 人工核对。告诉用户时说「结构校验通过」，不说成画面已经验证。手册顶栏会写上 skill 版本和生成日期。
- 生成成功后，把文件路径告诉用户，并说明：每个提示词右上角有「复制」按钮，点击后复制纯文本；打开方式是双击 HTML 文件，**用浏览器打开**（用编辑器或应用里的预览窗口打开，目录跳转和复制按钮可能不能用）。

## handbook.json 字段

最外层：

| 字段 | 类型 | 说明 |
|---|---|---|
| `project` | 文字 | 项目名，也是文件名的一部分 |
| `genre` | 文字 | 只能是 `短剧` 或 `影视` |
| `ratio` | 文字 | 画幅，如 `16:9`、`9:16`（开始前问过的） |
| `model` | 文字 | 模型版本，如 `Seedance 2.0`（脚本按 2.0→单段 15 秒、9 张图，2.5→30 秒、30 张图检查，超出只警告） |
| `script` | 列表（或一整段文字） | 剧本，每项 `{"title": 小节名, "body": 正文}`，按顺序显示 |
| `assets` | 列表 | 资产，每个人物或场景一项；没有就写 `[]` |
| `segments` | 列表 | 段落，每个生成片段一项，至少一项 |

**剧本**（`script` 里的每一项）：正文里换行保留；连续以 `|` 开头的行会显示成表格（人物信息表、场景信息表直接写 Markdown 表格就行）。只有表格和 `**加粗**` 会被渲染，其他 Markdown 写法会原样显示。通常的小节顺序：核心想法（短剧再加故事契约）、人物信息表、场景信息表、各场次。**体例统一用中文场号制**，动作行以「△」开头（见 `script-common.md`），不要混别的写法。

**资产**（`assets` 里的每一项）：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 资产编号，如 `人物1`、`场景1`；不能重复 |
| `name` | 是 | 名称，如 `老周`、`工地宿舍区` |
| `kind` | 是 | 类型，如 `人物`、`场景` |
| `prompts` | 是 | 提示词列表，每项 `{"label": 名称, "text": 提示词}`。`label` 决定它在【参考素材绑定】里的叫法：人物写 `人物四视图`（其他如 `状态版` 会写成「阿杰（状态版）@图2」），场景写 `母版`（叫主图）、`反打`（叫反打方向）、`俯视图`（同一个场景另有 `走位图` 时，段落不写 `use` 就只传走位图）、`角度图·说明`（单张角度图，叫另一个方向，例如 `角度图·朝板房`）、`场景多机位`（宫格，额度不够时用，叫其他角度）、`走位图`（叫走位示意图）；母版、反打、角度图加 `facing`（摄影机朝哪个方位拍：北、东北、东、东南、南、西南、西、西北），脚本用它查镜头朝的方向有没有图；道具写 `kind: 道具`，绑定行自动写「只参考外观和材质，画面里只有一个」 |

人物一般一条（`人物四视图`），场景按档位一到五条（`母版`、`反打`、`俯视图`、`角度图·…`、`走位图`）。**资产提示词里不要写全片统一的 `@图N`。** 反打写「参考@图1（场景母版）……」（只上传母版）；俯视图和角度图写「根据@图1和@图2（同一个场景的正打和反打）……」（上传母版和反打）；走位图写「在@图1（这个场景的俯视图）上……」（只上传俯视图）。

**其他类型的图**：例如尾帧锚定用的「上一段最后一帧」（见 `storyboard.md` 片段划分第 5 条），`kind` 写 `参考帧`；`label` 默认写 `状态参考`（脚本在【参考素材绑定】里自动写成只参考外观、不是首帧的那一行），只有下一段和上一段结尾同机位同景别接下去时才写 `衔接帧`（自动写成「@图N 为首帧」）；`text` 写一句给用户的说明（它是从上一段视频截出来的，不是生成的；不要写成提示词）。手册里它显示成说明，没有复制按钮，并在【参考素材绑定】里单独成一行。

**段落**（`segments` 里的每一项）：

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | 是 | 段落名，写场景加一句事件，如「工地宿舍区：老周接电话」 |
| `assets` | 否 | 这个段落用到的资产，如 `["人物1","场景1"]`；用到的全部都列。场景图只带本段镜头朝向的方向，写成 `{"id":"场景1","use":["母版","反打","俯视图"]}` |
| `concept` | 是 | 【整体概念】的内容 |
| `refs_extra` | 否 | 补充行，如参考视频、参考音频：`["参考视频：视频1，只参考运镜节奏"]`。图片的绑定行**不用写**，由脚本生成 |
| `cinematography` | 否 | 【摄影与影调】的内容；不需要就不要写这个字段 |
| `shots` | 是 | 镜头列表，每项 `{"title": "镜头1｜外景｜0-5秒｜中景", "body": 正文, "camera": 机位与运动, "summary": 画面要点, "lines": 台词}`，后三项用来生成镜头速览表（见 `storyboard.md`） |
| `sound` | 是 | 【声音】的内容 |
| `negative` | 是 | 【反向限制】的内容，以「以下内容一律不要出现：」开头 |
| `blocking` | 否 | 调度底稿的坐标：固定物、每个镜头的人物、摄影机、道具（格式见 `readback.md`） |
| `readback` | 否 | 只拿提示词文字盲读出来的同样格式的坐标，加上文字明写的画面左右、道具朝向和没写清的地方；有它时脚本画调度图并核对（见 `readback.md`） |

**`@图N` 怎么来的**：脚本按本段的 `assets` 自动生成【参考素材绑定】——先角色（按列出的顺序），再场景（按资产里提示词的顺序，例如主图、俯视图、其他角度、走位示意图）。**每个段落从 `@图1` 重新编号**，因为平台里的 `@图N` 是这一次生成里的**上传顺序**；同一张图在不同段落里编号可以不同。每段的提示词卡片上会显示「本段上传顺序」，用户照着上传即可。

**填写规则：**

- 各块的内容里**不要再写块名**（如 `【整体概念】`）。脚本按固定顺序拼出完整的视频提示词，并自动添加块名；写了会被去掉并给警告。
- `shots` 的内容必须和用户**确认过的分镜**一致，不要重新润色；`script` 也必须和用户确认过的剧本一致。整理时发现矛盾、错字或措辞问题，**先告诉用户、等他同意再改**，改了的每一处都要如实告诉他（见 `principles.md` 第 9 条）。台词原文只在 `shots` 里出现，`sound` 里不要重复写。
- `camera`、`summary`、`lines` 是镜头速览表用的，必须和 `body` 一致，不加新信息；`lines` 写「无」或「谁说、几个字」，**不抄台词原文**。
- 镜头标题行用全角竖线 `｜`；**镜头号全片连续**（第二段接着第一段的编号）；每个段落的镜头时间从 0 秒开始，连续、不重叠。格式不对脚本会警告。
- 字符串里的换行写成 `\n`，英文双引号写成 `\"`；最后一项后面不要有逗号。**最稳的做法是用脚本语言（如 Python 的 `json.dump(..., ensure_ascii=False)`）生成这个文件**，不要手敲大段转义。临时脚本**先写成 `.py` 文件再运行**，不要用管道或 heredoc 把长文本直接喂给 python：含中文引号的长文本在部分环境里会报编码错误（实测出现过）。

## 脚本生成的版式（固定）

**顶栏**：项目名、体裁、画幅、模型版本、skill 版本和生成日期。**左侧目录**：剧本、分镜、资产提示词（每个资产一条）、视频提示词（每一段一条）；窄屏时目录移到页面顶部，每一段单独占一行。

1. **剧本**：`script` 的各小节，表格显示成表格。
2. **分镜**：先是一张**片段划分表**（段落、场景、镜头范围、总时长、需要的参考图，由脚本从 `segments` 算出），再按段落：先是该段的**镜头速览表**（镜号、内外景、景别、机位与运动、画面要点、台词、时间），再是每个镜头的标题行和正文；有 `blocking` 或 `readback` 的段落，最后是**调度图**（每个镜头一个平面小图，两份数据时上下对照）和核对结论。
3. **资产提示词**：先是**资产编号表**（编号、名称、类型、图、用于哪几段），再是每个资产一张卡片，卡片里每条提示词一个「复制」按钮。**所有资产集中在这一节，每个资产只出现一次。**
4. **视频提示词**：放在**最后**，每一段一张卡片：「第一段提示词」「第二段提示词」……卡片上先是**本段上传顺序**（图1、图2……分别是哪个资产的哪张图，和提示词里的 `@图N` 对应），再是一整份视频提示词，右上角一个「复制」按钮。

使用顺序：先在「资产提示词」里生成所有资产图，再到「视频提示词」里，按某一段的上传顺序传图，粘贴这一段的提示词。

细节：整个文件是单个 HTML，不引用外部资源；浅色主题，系统深色模式下自动切换；点击「复制」后按钮变成「已复制」，2 秒后恢复；复制的只有纯文本，不带格式；目录里的链接用脚本滚动；打印时隐藏按钮和目录。

## 找 Python；没有就问用户要不要装

运行脚本前先找 Python 3.8 以上（脚本只用标准库）。依次试，**看输出是不是「Python 3.x」**，哪个能用就用哪个：

- `python3 --version`
- `python --version`
- Windows 再试 `py -3 --version`（Python 自带的启动器）。Windows 上 `python3` / `python` 可能只是应用商店的占位快捷方式，运行后没有版本号输出，不算找到。
- 都不行，再看常见安装位置：Windows 的 `%LOCALAPPDATA%\Programs\Python\Python3*\python.exe`，macOS 的 `/usr/bin/python3`、`/opt/homebrew/bin/python3`、`/usr/local/bin/python3`。

**都找不到时，不要直接退回 Markdown，先问用户要不要安装**（用提问器，没有就用文字列选项，见 `ask-before-start.md`）：

> 这台电脑上没有 Python，生成 HTML 导演手册需要它（约 30 MB，只用来运行手册脚本）。要我现在安装吗？
> 不装的话：只能给你一份 Markdown 文字版，没有一键复制按钮、左侧目录和排好的表格；分镜阶段的调度图画不出来；脚本的自动检查（时间写反、台词说太快、提示词超长、`@图N` 编号对不上、画面左右自相矛盾、缺图）都做不了，只能靠我人工核对，漏的可能更大。
> 选项：安装 Python（推荐）；不装，这次用 Markdown

**用户同意后才安装**，不同意或没回答都不装。按系统选命令：

| 系统 | 安装命令 | 装完怎么找到它 |
|---|---|---|
| Windows | `winget install -e --id Python.Python.3.12 --scope user`（装在用户目录，不需要管理员） | 当前终端的 PATH 不会马上更新：用 `py -3`，或 `%LOCALAPPDATA%\Programs\Python\Python312\python.exe` |
| macOS | 有 Homebrew：`brew install python`；没有：`xcode-select --install`（会弹出系统安装窗口，自带 python3，需要用户在窗口里点安装） | `/opt/homebrew/bin/python3`，或 `/usr/bin/python3` |
| Linux | `sudo apt install -y python3`（需要密码，请用户自己在终端运行） | `python3` |

- 装完重新检测一遍，能用了再运行脚本生成 HTML。
- 命令需要管理员权限、需要用户在窗口里点确认、没有 winget 或网络不通时，把命令和原因告诉用户，请他自己运行，装好后告诉你；这期间先把 `handbook.json` 存好。
- 不改用户的系统设置，不用别的来源的安装包。

## 降级：用户不装 Python，或者环境不能运行命令时

1. **不要手写 HTML**。
2. 按上面的版式，直接输出**同结构的 Markdown**：`# 项目名 · 导演手册`，然后 `## 剧本`、`## 分镜`（先片段划分表，再各镜头）、`## 资产提示词`（先资产编号表，再每个资产的提示词，提示词放进代码块）、`## 视频提示词`（每一段「第一段提示词」等，先写本段上传顺序，再把整份提示词放进代码块；`@图N` 同样按每段上传顺序从 1 编号）。
3. 明确告诉用户：**这次没有生成 HTML**，原因是没有 Python（或环境不能运行命令）；这一版没有一键复制和目录，调度图和脚本的自动检查都没做，是人工核对的；给出 `handbook.json` 和命令，装好 Python 后运行就能得到 HTML 和检查结果。

## 状态

脚本在 macOS（Python 3.9）上跑过示例并检查过校验提示；HTML 在内置浏览器里看过桌面、窄屏和深色三种样式。「复制」按钮在真实点击后显示「已复制」，写入剪贴板的文字和页面上的提示词逐字一致（用一次全新会话的真实产出验证过 8 个按钮）；目录链接在浏览器里点击能滚动到对应位置。**没有在 Windows、Linux 和各主流浏览器里逐一验证**，也没有读回剪贴板确认（浏览器不允许读）。**用应用内置的文件预览窗口打开时，目录跳转曾被用户反馈点击没反应**，原因没有复现，已改成脚本滚动，但那个环境里是否生效没有验证；建议用浏览器打开。
