# 导演手册（directors-book）

把一个想法一步步变成可以直接复制使用的文本：剧本、分镜、人物与场景的出图提示词、视频提示词，也可以整合成一个 HTML 导演手册。

## 四个阶段，每个都能单选

| 阶段 | 产出 |
|---|---|
| 剧本 | 短剧或影视剧本，统一的交接结构 |
| 分镜 | 镜头速览表、镜头正文（含镜头标题行）、片段划分表，以及按提示词回读校对过的调度图 |
| 资产包 | 人物提示词（人物四视图）、场景提示词（母版、反打、俯视图、按需的角度图、走位图） |
| 视频提示词 | 每个片段一份提示词 |
| **导演手册** | 上面四个阶段全做，交付一个 HTML（剧本、分镜、资产提示词、视频提示词） |

用户可以带上一阶段的成果直接开始（例如直接给分镜，只要视频提示词）。不要重做用户已经给出的阶段。

## 硬规则（每次都遵守，细节在对应文件里）

1. **术语配可见画面**：每个术语和情绪词后面都要有画面里看得见的东西；每句话问「这能被画出来吗」。**写清楚，不写满**：每个镜头先定必须看懂什么，关键动作写清楚，不按字数补写细节。→ `references/principles.md`、`references/video-prompt.md`「每个镜头写到什么程度」
2. **一个镜头不跨片段拆**：片段只在镜头边界断开。→ `references/storyboard.md`
3. **台词原文从分镜起只在【分镜】里写一次**：剧本是源头，不算；速览表、【声音】、资产里都不重复，只引用。
4. **开始前先问，用一个弹窗问完，顺序是体裁 → 时长 → 画幅 → 模型版本**（先定故事，再定制作）：**总时长**只在要由你来写剧本时问（用户只给了主题、想法或梗概），选项不写秒数：「按剧情估一个（推荐）」（你按故事先估一个，交付剧本时写明估的是多少秒）和「先看方向再定」（先给故事方向，选好方向后再定时长）；用户要自己定，就在选项下面的输入框里填秒数。按任务取舍，表和细节见 `references/ask-before-start.md`。
    - **每一次新的生成请求都重新问**，同一个对话里前面问过也一样（换了故事、再做一份、重新做，都算新请求）；每个问题把上次的选择排第一个、标「（上次）」。只有接着做同一份作品的下一阶段才沿用。
    - 体裁用户没明说就必须问，带了剧本、只给梗概都一样，不能自己推断；只做资产包时不问。用户给的只是故事梗概，不算带了剧本。
5. **资产按编号复用**：同一个人物或场景只出一份完整提示词，其他地方用编号引用，不重写。
6. **剧本不写摄影机**：不写镜头术语，分镜才管怎么拍。
7. **空间布局只定义一次**（门、家具这些实物之间的关系，在场景资产里写成一句，不写画面左右）：后面各处**原样复制**这一句，不改写，也不写「沿用」；画面左右每个镜头按机位推。母版、反打出图后和这一句不一样时，以图为准改源头这一句，再原样复制；反打、俯视图、角度图的提示词以图为准，不抄这一句（见 `asset-scene.md`）。
8. **不写「变形宽银幕」，不用片名、人名、摄影师名当锚点**。
9. **默认无配乐**，用户要才加。
10. **反向限制必写**：图像用图像底，视频用视频底，用「以下内容一律不要出现」开头。例外：反打、俯视图、角度图只写骨架里那几句；宫格的场景多机位、走位图用骨架里自带的版本（允许 V 标签，见 `asset-character.md`）。
11. **用户的明确要求优先于这里的默认写法**；时长、图片数量等数字按 `references/models.md`，用户可以覆盖。
12. **交付前过自检**：读 `references/checklist.md` 对应小节，缺项补齐再交付。导演手册用脚本生成 HTML；找不到 Python 时，用提问器问要不要安装，问题里写明不装的后果（只有 Markdown、没有一键复制、调度图和自动检查都做不了），用户同意才装（`references/handbook-html.md`）。
13. **用户确认过的剧本、分镜不擅自改**：发现矛盾、错字、措辞问题，先告诉用户、等同意再改；改了的每一处都如实说。前后矛盾（穿戴、道具、外观）要在交付前查出来。→ `references/principles.md` 第 9、10 条
14. **所有提问优先用提问器（弹窗）**：开始前的几问、每个阶段的确认、发现矛盾、要不要安装 Python，都先用提问器；每个问题带选项，选项下面用户都能自己输入；只有环境里没有提问器才用文字列出选项。**每个阶段交付的最后一步是提出确认问题，然后停下等回答**：剧本交付后问「剧本需要修改吗」，分镜交付后用一个问题问「分镜需要修改吗，接下来做什么」；补充了内容、发现矛盾、只给了主题要选方向时同样必问。没收到回答，不进入下一个阶段，也不替用户选。没有弹窗工具时用文字列出选项，只写一句「需要修改请告诉我」不算提问；有弹窗工具却用文字列选项也不算。→ `references/ask-before-start.md`
15. **先读懂场景，再按剧本的逻辑写调度**：剧情先定站位，机位跟着站位走，画面左右、面对还是背对镜头最后推出来；每个动作在场景图里要有走得通的路线，每个机位在参考图里要拍得到；人和关键物品的相对位置跨镜头不变，同一个人、同一件道具只有一个；镜头要拍参考图里看不到的区域，先补那个角度的场景图。**一切为剧本和剧情服务**：镜头数和机位由剧情和精彩程度决定，不为少出参考图少切镜头或改机位。→ `references/principles.md` 第 12 条、`references/camera.md` 基础第 15–19 条
16. **交付分镜前做提示词回读校对**：只拿提示词文字（不看剧本和调度底稿）还原出人物和摄影机调度，画图和调度底稿比；对不上就改提示词再读，最多三轮，三轮还不行停下问用户；交付分镜时用 `build_handbook.py --layout` 生成调度图页面给用户看。写完视频提示词再做一次。只有一个人、只朝一个方向拍、没有走动的段落，可以只做第二次。→ `references/readback.md`

## 开始前先问

读 `references/ask-before-start.md`。顺序是**体裁 → 时长 → 画幅 → 模型版本**，按任务跳过用不到的：只要剧本时不问画幅和版本；带了剧本也要问体裁（体裁影响分镜和视频提示词的摄影规则，手册里也要填），只做资产包时不问；时长只在要由你来写剧本时问（用户在输入框里填秒数，或选按剧情估、先看方向再定）。同一份作品里说过的不重复问；新的生成请求重新问。用户只给了主题、没有人物和事件时，先给 2–3 个核心想法让他选，不要直接写完整剧本，也不要问「要不要生成剧本」。

## 每个阶段交付时必须有

- **剧本**：统一交接结构（人物信息表、场景信息表、场次；每场有动作节拍、台词带语气、结尾状态）。
- **分镜**：每个镜头有标题行（`镜头1｜内景｜0-5秒｜中景`）加正文；一张镜头速览表（景别、机位与运动、画面要点、台词、时间）；一张片段划分表（段落、场景、镜头、总时长、需要的参考图）；按提示词回读校对过的调度图（`readback.md`）。
- **资产包**：每个人物一份人物四视图提示词；每个场景按需要的档位出母版、反打、俯视图、镜头要用的角度图、走位图，方向图写明朝向；一张资产编号表。
- **视频提示词**：每个片段一份，五个块齐全（影视体裁可再加【摄影与影调】）。
- **导演手册**：按 `handbook-html.md` 生成 HTML。

缺任何一项，说明没读全，回头补。剧本和分镜交付的最后一步，是硬规则第 14 条的确认问题。

## 导演手册的流程

1. 用户给剧本，或让你先写剧本；按体裁 → 时长 → 画幅 → 模型版本一起问（带剧本也问体裁；时长只在要你来写剧本时问）。
2. **先出剧本、再出分镜，每个交付后都按硬规则第 14 条提确认问题并停下等回答**：剧本问「剧本需要修改吗」；分镜问「分镜需要修改吗，接下来做什么」（一个问题，选项见 `ask-before-start.md` 第二节）。
3. 用户选了下一步就照做，不再另问。导演手册还是只要提示词，在分镜确认时一起问，**不要在开头问**；开头就说了要完整导演手册的，不再问。
4. 依次完成资产包、视频提示词，整理成 `handbook.json`（内容必须和用户确认过的剧本、分镜一致），运行 `scripts/build_handbook.py` 生成一个 HTML：版式是剧本 → 分镜 → 资产提示词 → 视频提示词（第一段、第二段……放在最后），提示词都可以一键复制。**不要手写 HTML**。找不到 Python 时先问用户要不要安装（同意才装），不装才退回 Markdown；字段、安装和降级办法见 `references/handbook-html.md`。

## 边界

- 本 skill 只产出文字提示词和 HTML 文件，**不调用任何生成服务，不上传素材**。唯一会动用户电脑的是：生成 HTML 找不到 Python 时，经用户同意安装 Python（见 `references/handbook-html.md`）。
- 这里的大多数写法来自对其他 skill、教程和实际出图反馈的整理，**没有做过系统的对照实验**。遇到效果不好，先按 `principles.md` 的「出错只改出错的那一层」排查，并如实告诉用户哪些写法是默认的、没有在他的平台上验证过。
