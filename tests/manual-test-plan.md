# directors-book 全新会话实测方案

目的：确认**全新的 agent 会话**读得全、问得对、产出合格。测的是 skill 本身，所以开场话术里**不要透露 skill 的内部规则**，让 agent 自己从 `SKILL.md` 一路读下去。

## 0. 准备

1. 安装（复制，不要用软链，软链能否被识别我没验证）：

```bash
mkdir -p ~/.claude/skills && cp -R "<仓库路径>/skills/directors-book" ~/.claude/skills/
```

   改了 skill 后重测：先 `rm -rf ~/.claude/skills/directors-book`，再重新复制。

2. 在一个**空文件夹**里开新会话，别在放着调研资料的目录里开，否则 agent 会读到不该读的东西：

```bash
mkdir -p ~/skilltest && cd ~/skilltest && claude
```

3. 本机 `~/.claude/skills/` 里还有别的 skill（例如 `vibe-video-retro-print`）。如果触发的是别的 skill，也算一个发现，记下来。
4. 每轮测试开始前确认 `python3 --version`（需要 3.8 及以上），否则导演手册那一步会走降级。
5. 用 Claude Code 测的时候，每次读文件都会显示 `Read` 调用，**用这个核对它读了哪些文件**。在 claude.ai 里看不到，只能看产出。

> **第 1 次实测的教训**：开场时不要说「用 manual-test-plan.md 里的话术」，要**把话术原文粘贴进去**。否则 agent 会去读这份文件，事先看到所有检查项和预期，测试就不准了（第 1 次就是这样，见 `results-2026-10-17-run1.md`）。最好把这份方案放在 agent 找不到的地方再测。

## 1. 主线测试（一个会话走到底）

测试故事（虚构，两场戏、约 25–30 秒，用来验证两个段落和资产只出现一次）：

> 深夜，外卖员阿杰把一份餐送到老小区三楼。开门的是他三年没联系的哥哥。哥哥让他进屋坐，阿杰把餐放在门口，说了句「餐到了，别忘了给好评」，转身下楼。哥哥站在门口，没有追。楼下，阿杰骑上电动车，没有发动，坐了很久。

### 第 1 轮：开场（测触发、提问顺序）

**话术 A（主测）**，直接粘贴：

```
我想做一个短剧，从剧本开始，一路做到可以直接复制使用的导演手册。故事：深夜，外卖员阿杰把一份餐送到老小区三楼。开门的是他三年没联系的哥哥。哥哥让他进屋坐，阿杰把餐放在门口，说了句「餐到了，别忘了给好评」，转身下楼。哥哥站在门口，没有追。楼下，阿杰骑上电动车，没有发动，坐了很久。总长大约25到30秒，两场戏。
```

**预期**：skill 被触发；读了 `SKILL.md`；**只问画幅和模型版本**（我已经说了短剧，所以不问体裁），两项**一次问完**，画幅在前：有弹窗工具就是同一个弹窗里的两个问题，没有就是同一条文字消息。弹窗里每个问题都能自己输入（「其他」）。

- 如果它没有触发 skill：记下来，再补一句「用 directors-book 这个 skill」，继续测后面。
- 如果它直接开始写剧本、没问画幅和版本：问题（见第 3 节记录）。

**回答**：

```
竖屏，Seedance 2.0
```

**预期**：弹窗里选了带比例的选项，就不再回显确认；如果你是**输入**「竖屏」，它把画幅**回显**为 9:16 让你确认（只说竖屏时按 9:16 并回显）。回显后你说「对」。

### 第 2 轮：剧本

**预期**：先写核心想法和戏剧性前提，再给剧本。读过 `script-common.md`、`script-shortdrama.md`（短剧）。

### 第 3 轮：分镜

你说：`剧本没问题，继续做分镜`

**预期**：读过 `storyboard.md`、`camera.md`、`performance.md`、`models.md`。产出镜头表和片段划分表。**这一步先不要说「生成手册」**，看它会不会自己在分镜确认后问「是否生成导演手册」。

接着测**改分镜**：随便挑一个镜头，说 `镜头2 改成特写，哥哥的反应再收一点`。**预期**：只改这个镜头，时间段仍连续，不推翻其他镜头；改完没有破坏相邻镜头的衔接。

最后说：`分镜确认了`。**预期**：它在这时弹窗问**接下来要什么**（导演手册、只要提示词、到分镜为止）；**开头没有问过「做到哪一步」或手册**。

### 第 4 轮：导演手册

你说：`生成导演手册`

**预期**：依次做资产包和视频提示词，写出 `handbook.json`，运行 `build_handbook.py`，交付 `项目名_导演手册.html`。读过 `asset-character.md`、`asset-scene.md`、`video-prompt.md`、`handbook-html.md`。

打开 HTML，点每个「复制」按钮，粘贴到记事本，看内容是否完整。**这一步正好验证我没能验证的「别处粘贴是否一致」。**

## 2. 检查项

打勾标准：看**产出和读取记录**，不要凭印象。

### A. 触发与读取

- [ ] 说「做短剧」就触发了 directors-book。
- [ ] 每个阶段动笔前，读了路由表里要求的文件（`SKILL.md` 的路由表）：

| 阶段 | 应该读过 |
|---|---|
| 短剧剧本 | `principles.md`、`script-common.md`、`script-shortdrama.md`、`checklist.md` |
| 分镜 | `principles.md`、`ask-before-start.md`、`models.md`、`storyboard.md`、`camera.md`、`performance.md`、`checklist.md` |
| 资产包 | `principles.md`、`ask-before-start.md`、`models.md`、`asset-character.md`、`asset-scene.md`、`checklist.md` |
| 视频提示词 | `principles.md`、`ask-before-start.md`、`models.md`、`video-prompt.md`、`performance.md`、`camera.md`、`checklist.md` |
| 导演手册 | 上面全部，再加 `handbook-html.md` |

- [ ] 一开始（问问题之前）就读了 `ask-before-start.md`；`SKILL.md` 的「开始前先问」要求这样做，路由表的剧本行里没列它。
- [ ] 交付前它回头核对了 `checklist.md` 对应小节（不是凭印象）。
- [ ] 没有读无关的文件，也没有跳读后凭印象写。

### B. 提问

- [ ] 只问了画幅和版本；没有重复问体裁。
- [ ] 两项一次问完（同一个弹窗或同一条消息），顺序是画幅 → 版本；没有拆成两轮。
- [ ] 弹窗里每个问题都能自己输入。
- [ ] 你自带了剧本、没说体裁时，也问了体裁（问法是「这份剧本按短剧还是影视来拍？」）。
- [ ] 你只说「继续做资产和视频提示词」、没说要不要手册时，仍然问了「接下来要什么」；开头就说「根据这个剧本出完整的导演手册」时，没有再问。
- [ ] 只给故事梗概、没有说体裁时，问了体裁（没有自己根据故事内容推断，也没有当成「已带剧本」）。
- [ ] 只给一个主题（例如「亲情」「雨夜」）、没有人物和事件时，体裁等问完之后，弹窗给了 2–3 个一句话的核心想法让你选，没有直接写完整剧本，也没有问「要不要生成剧本」。
- [ ] 剧本交付后、分镜交付后、剧本和分镜都确认后的「接下来要什么」，以及它补充内容时的「要沿用吗」，都用了弹窗（环境有弹窗工具的话），不是只在文字里问；开头没有问「做到哪一步」。
- [ ] 选了带比例的选项就没有再确认；输入了「竖屏」或「横屏」的，回显了比例。
- [ ] 问完之后没有再重复问。

### C. 剧本

- [ ] 先有一两句话的核心想法或前提。
- [ ] 有人物信息表、场景信息表、场次；每场有结尾状态。
- [ ] 场次是中文场号制：「第N场　内外景　地点　时段」，动作行以「△」开头，台词行是「角色（语气）：台词」；第一拍是具象画面；前 3 拍内出现钩子。
- [ ] 剧本里没有镜头术语（特写、切、POV、「我们看到」）、没有镜号。
- [ ] 动作拍得出来：没有「想」「回忆」「意识到」；没有写细微表情。
- [ ] 台词带语气，语气不超过 3 个词。
- [ ] 你给的那句「餐到了，别忘了给好评」原样保留，没被润色。
- [ ] 结尾写成了确定状态，不是单纯的悬念。

### D. 分镜

- [ ] 每个镜头一行标题：`镜头1｜外景｜0-5秒｜中景`，**全角竖线**。
- [ ] 时间段连续、不重叠；每个片段不超过 15 秒（2.0）。
- [ ] 没有一个镜头被拆在两个片段里。
- [ ] 有片段划分表（段落、场景、镜头、总时长、需要的参考图）；两场戏分成了两个段落。
- [ ] 每个片段有**镜头速览表**（镜号、内外景、景别、机位与运动、画面要点、台词、时间）；表和正文一致，台词列只写「无」或「谁说、几个字」，没有抄原文；你让它改某个镜头时，正文和表里这一行一起改。
- [ ] 做过合镜检查，不合并的写了理由。
- [ ] 没有单独的台词表格；台词嵌在镜头正文里，格式是 `角色（语气）+ 动作 + 说："台词"`。
- [ ] 走动的人（阿杰下楼、骑车）有起点、路径、终点，落到了画面位置。
- [ ] 竖屏稿里没有写「左右对峙」「大幅横向位移」。
- [ ] 没有写「变形宽银幕」，没有用片名或人名当锚点。
- [ ] **分镜确认前，没有擅自开始写资产包和视频提示词。**
- [ ] 你说「不改」「确认」之后，它没有再改剧本或分镜；发现问题是先告诉你、等你同意（第 1 次实测里出过这个问题）。
- [ ] 人物的穿戴和随身物品前后一致，没有「摘下已经戴着的东西」这类矛盾，信息表和动作对得上。
- [ ] 每个镜头的六项都「够」（标准见 `video-prompt.md` 的表）：不求写满，但表情有 1–2 个可见变化（转折点镜头 3 个以上先后变化，不是「平静」「克制」），每个镜头有环境里在动的东西；确实不适用的项在交付说明里列出了。
- [ ] 镜头号全片连续（第二段接着第一段数）；每个镜头不是概要，写出了人物位置和走位、表情的可见变化、手和道具、环境里在动的东西；脚本没有「镜头正文偏短」的警告。
- [ ] 关键道具（如怀表、餐袋）在它出现的每个镜头里都写了位置，不是只在放下的那个镜头写一次；拿起、放下写了手和落点。
- [ ] 剧本和分镜都确认后，才问接下来要什么（导演手册还是只要提示词）。

### E. 资产包

- [ ] 阿杰一份人物四视图提示词，块齐全：版式、人物身份、皮肤状态（两层）、服装、光影关系、镜头质感、情绪、反向限制。
- [ ] 有年龄锚；污渍写了颜色、部位、面积；衰老细节写得轻。
- [ ] 哥哥也有人物提示词（他有镜头），或者说明为什么没有。
- [ ] 场景按档位出图：不同场景按需要出母版、场景多机位；简单场景没有硬加走位图。
- [ ] 空间布局只写了一次（门在画面哪一侧等），后面是引用。
- [ ] 场景母版含主机位 A，画幅是竖屏；有光学柔化、远景偏软、不要青橙；图里没有人。
- [ ] 场景多机位是 2×2 共 4 格，第 1 格是主机位 A；提示词开头写了「根据@图1（场景母版）……」。
- [ ] 反向限制以「以下内容一律不要出现」开头，有图像底。
- [ ] 有资产编号表。

### F. 视频提示词

- [ ] 块齐全：整体概念、参考素材绑定、分镜、声音、反向限制（短剧默认没有【摄影与影调】）。
- [ ] 【整体概念】里没有时长、画幅、模型版本。
- [ ] 【参考素材绑定】角色一行、场景一行；编号和资产编号表一致。
- [ ] 台词原文只在【分镜】里出现，【声音】里没有重复。
- [ ] 默认无配乐，【声音】里写了无配乐。
- [ ] 随机挑三个形容词问「这能被画出来吗」；画不出的算问题。
- [ ] 不同段落没有混用 2.0 和 2.5 的数字。

### G. 导演手册

- [ ] 写出了 `handbook.json`，用脚本生成，**没有手写 HTML**。
- [ ] 脚本没有报错；如果有警告，它读了并处理。
- [ ] 文件名 `项目名_导演手册.html`，用浏览器能直接打开，离线可用。
- [ ] 顺序是剧本 → 分镜 → 段落；分镜里的片段划分表和你确认的一致。
- [ ] 资产提示词集中在「资产提示词」一节，每个资产只出现一次；视频提示词放在最后，按第一段、第二段排列。
- [ ] 每个资产提示词和每份视频提示词都有「复制」按钮，点击后变成「已复制」，2 秒后恢复。
- [ ] **粘贴出来的内容和页面上显示的一致**，换行没丢，没有多余的缩进或 HTML 标签。
- [ ] `handbook.json` 里每个镜头都有 `camera`、`summary`、`lines`，手册「分镜」一节每段都有速览表；视频提示词里没有出现速览表的内容。
- [ ] 视频提示词里的【分镜】和你确认过（含你改过的镜头2）的分镜**逐字一致**（半角改全角除外）。
- [ ] 第二个段落的 `@图N` 从 `@图1` 开始连续编号（不是全片统一编号）；每个段落有「本段上传顺序」。
- [ ] 场景多机位、走位图的提示词里提母版时写的是 `@图1`。
- [ ] 提示词里没有「主机位A」「母版」「场景多机位」这类内部术语；标点是全角。
- [ ] 它告诉了你文件位置、怎么打开。

## 3. 单项测试（每项开一个新会话，很快）

| 编号 | 话术 | 预期 |
|---|---|---|
| S1 | `帮我写一个短剧剧本，故事是……（随便一句话）` | 不问画幅和版本；只出剧本，不擅自继续做分镜 |
| S2 | 粘贴一份你自己的短剧剧本（几场戏就行）：`这是我的剧本，帮我做分镜` | **不问体裁**，问画幅和版本；**不改你的台词**；发现硬伤只报告 |
| S3 | 主线话术 A 之外加一句：`我的平台单次最长 10 秒，最多 6 张图` | 用你的数字覆盖默认值，每个片段 ≤10 秒、图片数 ≤6，并说明用的是你的数字 |
| S4 | 在主线最后一步前说：`不要运行任何命令` | 走降级：输出同结构的 Markdown，并**明确告诉你这次没有生成 HTML**；没有手写 HTML |
| S5 | 做视频提示词时说：`整体用王家卫的风格` | 不把人名写进提示词，改成具体可见的东西（色调、光源、运动）；并告诉你它这样做了 |
| S6 | 在 Codex 里测：安装到 `~/.agents/skills/directors-book/`，用话术 A | 和 Claude 的表现对照：触发、读取、提问顺序是否一致 |

S6 的安装命令：

```bash
mkdir -p ~/.agents/skills && cp -R "<仓库路径>/skills/directors-book" ~/.agents/skills/
```

## 4. 记录问题

每发现一个问题，记一行，给我就能定位：

| 阶段 | 现象（贴原文片段或截图） | 违反的规则（对应的文件和位置） | 是它没读到，还是读到了但没照做，还是 skill 本身写得含糊 |
|---|---|---|---|

后面一列最重要：

- **没读到**：路由表或 `SKILL.md` 的指引不够强，我来改路由和硬规则。
- **读到了没照做**：规则太靠后或太长，我来精简、前置、改成可检查的句子。
- **skill 本身含糊**：我来改措辞和示例。

## 5. 不用担心的事

- 画面效果、出图好不好看：这份测试只测**文字产出和流程**，不调用任何生成服务。
- 提示词字数：没有上限，不算问题。
- 同一份话术两次结果略有不同：正常，关注规则有没有被违反。
- 我已知**没验证**的：2.0 和 2.5 的数字（第三方来源）、复制到别处粘贴的一致性、场景多机位和走位图出图效果、「抗 AI 感」措辞的实际效果。测到这些，记下现象即可，不用当成 skill 的错。
